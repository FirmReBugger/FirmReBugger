# Bug Description

`sms_check` parses the modem's SMS response by locating a required marker with
`strstr`. It saves that return value, then uses it directly as the first
argument to a second `strstr` call. The null check occurs only after the second
call. An SMS response that omits the first marker therefore passes a null
haystack into the C library search routine, which dereferences address zero and
faults instead of rejecting the malformed response.

The fix is to check the first search result immediately and abandon parsing
before making any further string operation when it is null.

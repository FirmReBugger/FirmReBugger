# Bug Description

uTasker's `fnDoCommand` includes an `M`/modify-memory handler. It parses the address token from console text with `fnHexStrHex`, retains the resulting integer as a pointer, parses the requested value, and performs a raw 32-bit or byte store through that pointer.

There is no range, alignment, ownership, or permission check between parsing the text and executing the store. Any address that can be expressed by the command is accepted. An unmapped address causes an immediate fault, while an address in RAM or a writable peripheral region modifies the selected target.

This provides an arbitrary-memory-write primitive to anyone who can access the debug console. It can alter variables, callback pointers, scheduler structures, or device registers without passing through the normal firmware APIs. The handler must restrict writes to explicitly intended regions and validate width, alignment, and authorization before dereferencing the parsed address.

# Bug Description

The global `timer_handles[]` array is meant to hold pointers to persistent
`TIM_HandleTypeDef` structs so `HAL_TIM_IRQHandler` can look one up when a
timer interrupt fires. The PWM-start code path populates `timer_handles[1]`
with the address of a **stack-allocated** handle rather than a
static/global one, so the pointer dangles as soon as that function returns.

Once that happens, any later timer interrupt that consults
`timer_handles[1]` dereferences whatever now happens to occupy that stack
slot — stale data left behind by whichever function most recently used that
region of the stack — instead of the original handle it was meant to point
to.

This is a textbook escaping-stack-pointer bug: taking the address of a
local variable and stashing it somewhere that outlives the function it
belongs to.

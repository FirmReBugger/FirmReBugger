# Bug Description

RIOT's shell `rtc` command parses a date/time argument with `_parse_time`,
which pulls the year, month, day, hour, minute, and second fields out of the
input string with `strtol` and stores each one directly into the target
`struct tm` — none of the fields are checked against any valid range before
being stored.

`_parse_time` then calls `dow()` (Sakamoto's day-of-week algorithm) to
compute the day of week for the parsed date, passing the unchecked month
value straight through. `dow()` uses that month to index a fixed 12-entry
lookup table with no bounds check of its own, since the algorithm assumes a
valid 1–12 month to begin with. A month value outside that range indexes far
past the table, reading whatever memory happens to sit at that offset — and
for a sufficiently large or negative month, that address is unmapped and the
firmware faults.

This is reachable through ordinary use of the shell's `rtc` command with an
out-of-range month field — no special framing or malformed protocol data is
needed, just a numeric field the parser never validates.

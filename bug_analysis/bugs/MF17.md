# Bug Description

`sicslowpan::input` converts the fragment header's offset from eight-octet
units to a byte offset and uses it to place the fragment payload in a fixed
400-byte reassembly slot. The copy path does not enforce the combined bound
`offset + payload_length <= 400`. A fragment can therefore begin outside the
slot or begin near its end and extend past it, causing `memcpy` to overwrite
adjacent Contiki state. The corruption can remain latent until unrelated code
later consumes the damaged state and faults.

The fragment offset and payload are network-controlled fields defined by
[RFC 4944 section 5.3](https://datatracker.ietf.org/doc/rfc4944/). The
ATSAMR21G18A integrates an AT86RF233 IEEE 802.15.4 radio, so a peer can supply
the fragmented packet through the target's physical radio interface. The
unsafe destination calculation occurs in CPU software after reception, making
the out-of-bounds write hardware-reachable.

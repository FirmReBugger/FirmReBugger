# Bug Description

The old `uncompress_hdr_iphc` implementation advances through attacker-supplied
compressed header fields without consistently checking the remaining input or
the remaining capacity of its output buffer. Length and compression fields can
therefore make it read beyond the received packet and copy decompressed data
beyond `packetbuf` or the selected 148-byte `frag_info.first_frag` reassembly
buffer.

Upstream fixed the defect through a sequence of changes that made
decompression return failure, propagated that failure to the caller, tracked
the destination size, checked each read and write, and corrected an off-by-one
loop condition.

# Bug Description

The BLE L2CAP input path derives a channel-array index from the 16-bit channel
identifier carried in a received packet. Its bounds comparison truncates that
index to eight bits, but the subsequent channel-pointer calculation uses the
full value.

An index with a nonzero upper byte can therefore pass the check whenever its
low byte falls within the accepted channel range. The full index is then
multiplied by the channel-structure size and added to the channel-array base,
producing a pointer outside the array.

The input path immediately reads fields through this invalid pointer. A
malformed channel identifier can consequently cause an out-of-bounds read,
crash the network stack, or make unrelated memory be interpreted as channel
state.

The channel identifier is supplied directly by network input.

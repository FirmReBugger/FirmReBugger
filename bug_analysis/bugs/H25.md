# Bug Description

This is **CVE-2023-24823**. During 6LoWPAN IPHC transmission, `_iphc_encode` calculates the output allocation from packet-snippet types. It assumes that every `GNRC_NETTYPE_UNDEF` snippet represents a UDP header and reserves only eight bytes for it.

Forwarding can leave IPv6 extension headers in an untyped snippet. The later encoding loop does not rely on the snippet type; it follows the IPv6 next-header fields and may select Hop-by-Hop, Routing, Fragment, Destination Options, or another extension-header encoder. Those headers can be much larger than the eight-byte allocation chosen earlier.

The encoder consequently writes the larger compressed extension header into a UDP-sized buffer, overflowing packet storage and potentially corrupting allocator metadata or adjacent packets. Allocation and encoding must classify the snippet consistently, or the allocation must use the actual extension-header length before any output is written.

# Bug Description

This is **CVE-2023-1423**. The H4 UART receive ISR normally performs lightweight FIFO work and defers Bluetooth host processing to a thread. Priority HCI events are different: `read_payload` calls `bt_recv_prio` synchronously while still on the interrupt stack.

For an HCI Number Of Completed Packets event, priority processing can release the final reference on an ACL receive buffer. The buffer's destroy callback, `report_completed_packet`, calls `bt_hci_cmd_create` to construct a controller command. That function requests a buffer from `hci_cmd_pool` with `K_FOREVER`.

A blocking allocation cannot wait and reschedule from ISR context. If the pool is exhausted, allocation returns NULL. `bt_hci_cmd_create` protects the result only with `__ASSERT_NO_MSG`, which is compiled out in the release build, and then passes the NULL buffer to `net_buf_reserve`. The reserve operation writes through the embedded-buffer offset from NULL. Priority event handling must defer this work or handle allocation failure explicitly before dereferencing the result.

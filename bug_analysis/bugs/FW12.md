# Bug Description

`FirmataClass::setPinState`/`getPinState` compute their target address as
an offset into a `pinState[]` array embedded in the `Firmata` object,
indexed directly by the raw pin number from the wire protocol — with no
bounds check against the array's real size. That pin number comes straight
from a Firmata `SET_PIN_MODE` message, fully attacker-controlled.

A pin number past the array's real bound (for example, `90`) computes an
address that lands past the end of the `Firmata` object entirely, inside
the neighboring `timer_handles[]` array. `setPinState` then writes the
caller-supplied state value there, corrupting whatever timer handle data
happens to occupy that slot.

Because `timer_handles` stores pointers used by later timer dispatch, this
out-of-range pin write can corrupt sensitive callback state.

# Bug Description

The libmaple USB low-priority interrupt handler expects global property and endpoint callback structures to have been installed by `usbInit`. It loads the callback owner from `pProperty` and dispatches through fields in that object without checking whether USB initialization ran.

In this Marlin build, `board_setup_usb` is empty and no path calls `usbInit`. The USB globals therefore remain at their zero-initialized BSS values. If `USB_LP_CAN_RX0` is entered anyway, the handler immediately follows a NULL property pointer and faults.

# False Positive Reason

The STM32F103RET6 NVIC line is disabled at reset. The only code that enables the shared USB low-priority/CAN receive interrupt is the unused `usbInit` routine. Since this firmware never enables the line, the physical MCU cannot enter the handler with the zeroed USB structures. The failure requires interrupt injection that ignores NVIC state; reset behavior is documented in [PM0056](https://www.st.com/resource/en/programming_manual/pm0056-stm32f10xxx20xxx21xxxl1xxxx-cortexm3-programming-manual-stmicroelectronics.pdf).

# Bug Description

`execute` allocates `argv[CONFIG_SHELL_ARGC_MAX + 1]` but continues while
`cmd_lvl <= CONFIG_SHELL_ARGC_MAX`. At `cmd_lvl == 12`, it passes `&argv[12]`
to `shell_make_argv` with room for only one pointer while permitting two
arguments. The parser's contract requires an additional slot for the trailing
NULL, so its `argvp[2] = NULL` store is one word beyond the array.

The out-of-bounds store overwrites `execute`'s saved `r4`, changing the saved
shell pointer to zero. After `execute` returns, prompt output follows that null
pointer to an indirect branch at address zero. The loop must stop before a
parse whose arguments plus terminator exceed the remaining array capacity.

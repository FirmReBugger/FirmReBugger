# Bug Description

`FirmataParser::processSysexMessage` handles the Firmata `STRING_DATA`
(`0x71`) sysex command by calling `decodeByteStream(bytec, bytev)` with
`bytec = sysexBytesRead - 1` and `bytev` pointing a few bytes into the
`Firmata` object's own memory (`Firmata+3`) — `sysexBytesRead` is simply the
number of data bytes the host sent before the terminating `0xF7`, buffered a
byte at a time with no check against any fixed buffer capacity. A sysex
message with the maximum 7-bit-representable byte count (127) is accepted
as-is.

`decodeByteStream` itself is a correct in-place 7-bit-stream decoder (it
reads two encoded bytes and writes one decoded byte, so the write cursor
never runs ahead of the read cursor) — the defect is that its caller trusts
an unbounded, attacker-controlled `bytec` and points it at a buffer inside
the `Firmata` object that isn't sized for anywhere close to 127 bytes.
Writing decoded bytes starting at `Firmata+3` for a large `bytec` walks
straight through the rest of the object's fields, including the embedded
`FirmataMarshaller` — whose first member is the `Stream*` it writes
MIDI/Firmata responses to.

The corruption and the eventual crash happen in two unrelated exchanges: a
`STRING_DATA` sysex message overwrites the marshaller's stream pointer with
no immediate symptom, and the firmware only crashes later, on the next
unrelated `REPORT_FIRMWARE` request, when it tries to send its response
through the now-corrupted pointer.

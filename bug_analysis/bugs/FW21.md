# Bug Description

The STM32 Arduino core's `HAL_UART_TxCpltCallback` looks up a per-UART
callback function pointer and calls it directly, with no check that the
slot is non-NULL. That table only gets populated for a given
`HardwareSerial` instance once it's actually started (`.begin()`).

# False Positive Reason

`Serial2` is instantiated as a global object by the STM32 core regardless
of whether it's used, but this sketch never has any reason to start it —
its Firmata communication runs entirely over the primary serial port. A
TX-complete interrupt for a UART can only legitimately fire on real
hardware after that UART has actually been used to transmit, which requires
it to have been initialized first. Reaching this code for an unused, never
-initialized `Serial2` isn't something real UART/Firmata traffic can
produce.

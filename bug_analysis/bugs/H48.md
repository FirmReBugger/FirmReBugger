# Bug Description

ATT response-timeout processing spans request transmission, response reception, and final status handling. A historical defect allowed the associated ATT channel to be cleared or lost while one of those paths still assumed it was valid, creating a possible NULL-pointer dereference during timeout completion.

The affected operations must either retain the channel for the lifetime of the outstanding request or check that it still exists before using channel state.

# False Positive Reason

This firmware includes the Zephyr fix that coordinates the channel lifetime and guards the relevant sent, receive, and status paths. Outstanding requests no longer reach those operations with a NULL channel. The entry describes a regression condition for an older implementation, not a defect present in this build.

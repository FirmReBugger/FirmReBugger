# Bug Description

`cmd_config` accepts a device name from the shell and resolves it with the subsystem-neutral `device_get_binding`. That lookup can return any registered Zephyr device, including GPIO, UART, PWM, or CAN objects.

The command then passes the returned object to `can_configure` without verifying its subsystem. The inline CAN wrapper interprets `dev->api` using the CAN API layout and calls the configuration slot with CAN-specific arguments. For a non-CAN object, that slot belongs to another API or contains an incompatible pointer, producing cross-subsystem type confusion and an invalid indirect call.

The handler must verify that the resolved device exposes the CAN API before dispatching, rather than treating successful name lookup as proof of type.

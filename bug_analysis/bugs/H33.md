# Bug Description

Zephyr semaphores contain an embedded wait queue that `k_sem_init` must initialize before the object is used. The Bluetooth transmit path calls `k_sem_take` on the LE packet-credit semaphore and assumes that initialization completed successfully.

When the semaphore initializer rejects its arguments, the structure remains at its zeroed BSS value. `k_sem_take` can still observe a count of zero and enter the blocking path. `z_pend_curr` and the priority-queue helper then attempt to append the current thread to the semaphore's wait list.

An initialized empty list contains self-referential head and tail sentinels. The zeroed object instead supplies a NULL tail, so `sys_dlist_append` stores through address zero while linking the waiter. Code that publishes a semaphore must check initialization errors and must never allow `k_sem_take` to receive an object whose wait queue was not constructed.

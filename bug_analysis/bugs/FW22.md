# Bug Description

`I2C_ITError` handles bus-error recovery and discards a byte by writing it through `hi2c->pBuffPtr`. The store has no local NULL check; it assumes that an active receive operation has installed a valid cursor.

If the handler is entered while the driver's own state says it is idle, `pBuffPtr` may still be NULL or unrelated to an active transfer. The recovery store would then write through invalid state even though no receive buffer is owned by the handler.

# False Positive Reason

A real slave STOP or bus-error event with data to discard implies that an addressed I2C transaction is active. The driver transitions out of idle and installs its transfer state before enabling the corresponding interrupt handling. The contradictory combination—idle software state plus an event that requires an active transaction—depends on synthetic interrupt timing independent of peripheral state and is not produced by real I2C bus activity.

# Bug Description

`fnExtractFIFO` copies received USB data from the OTG_FS FIFO into a fixed 64-byte slot assigned to an endpoint. It reads a hardware-reported receive byte count, chooses a small specialized copy for a few fixed lengths, and otherwise enters a generic word-copy loop.

The generic loop repeatedly loads a word from the FIFO and stores it through an incrementing destination pointer. Its loop bound is derived from the reported length, but no comparison limits that length to the 64-byte endpoint slot. Once more than 64 bytes are requested, stores continue into the next slot and then into unrelated global memory.

The overwritten region can contain endpoint metadata, driver-table pointers, or other callback state. The corruption may remain latent until another USB or interrupt path consumes one of those objects, so the eventual invalid access need not occur inside `fnExtractFIFO`. The receive count must be rejected or capped before the copy begins.

# Bug Description

`rpl_ext_header_srh_update` reconstructs an address pointer from a type-3 RPL
source-routing header. The pointer depends on the routing-header location,
the selected path index, and the encoded address-compression fields.

Before using the pointer, the function does not verify that the address and
all `16 - cmpr` bytes referenced from it remain inside the IPv6 packet
buffer. Malformed routing-header fields can therefore produce a pointer near
or beyond the end of that buffer.

The function first copies the selected address suffix into the IPv6
destination address and then writes the previous destination suffix back to
the selected route slot. An invalid derived range consequently causes an
out-of-bounds read followed by an out-of-bounds write. This can disclose
adjacent bytes to the address-processing logic, corrupt network state, or
redirect later control flow.

The source-routing header is supplied by network input, so an attacker able
to deliver a malformed IPv6 routing header can reach the faulty calculation.

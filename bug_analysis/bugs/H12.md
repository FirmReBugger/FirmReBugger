# Bug Description

`input_l2cap_credit` handles received L2CAP credit signals by looking up the
channel associated with the packet sender. The lookup returns `NULL` when the
sender has no registered channel.

Although the handler validates the credit signal's length, it does not check
the lookup result before reading the channel's credit fields. A syntactically
valid credit signal from an unregistered sender therefore causes a NULL
pointer dereference and terminates packet processing.

The signal and sender address are supplied by received network traffic, so an
unregistered remote sender can reach the faulty path without establishing a
channel first.

# Bug Description

The `ccnl_cs` shell command decodes percent escapes in URI components without
restricting their values. `%00` produces a leading null byte, and malformed
escapes whose digits are not hexadecimal can produce the same value. When the
command serializes and parses that name, the NDN-TLV decoder interprets a
leading null as a segment-number marker. A sufficiently large remaining value
is rejected and the decoder returns a null packet.

The shell command does not check that parse result. It wraps the null packet in
a content object and submits it to the content store. A later content-store
operation dereferences the missing packet and its prefix, causing an invalid
memory access. The URI decoder must reject malformed or forbidden escapes, and
the shell path must reject a failed packet parse before creating or caching
content.

# Bug Description

`bt_init` parses the controller's LE Read Buffer Size response. It loads the controller-supplied `le_max_num` byte and calls `k_sem_init(&bt_dev.le.acl_pkts, le_max_num, le_max_num)`, using the same value for the initial packet-credit count and semaphore limit.

`z_impl_k_sem_init` validates the limit before touching the semaphore object. When `le_max_num` is zero, the initializer returns `-EINVAL` because a zero limit is invalid, leaving the embedded wait queue, count, and limit unchanged. `bt_init` discards that return value and proceeds as if initialization succeeded.

The uninitialized semaphore is later consumed by the Bluetooth transmit path. A blocking take attempts to link a waiter into the still-zero wait queue and dereferences a NULL list pointer. The root cause is the ignored initialization failure: `bt_init` must validate the response, check `k_sem_init`, and abort or retry Bluetooth setup before publishing the semaphore.

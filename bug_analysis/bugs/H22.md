# Bug Description

During 6LoWPAN IPHC decompression, `gnrc_sixlowpan_iphc_recv` advances a
payload offset while decoding the compressed header. It then calculates the
payload-copy length as `sixlo->size - payload_offset` without rejecting an
offset larger than the packet snippet.

A crafted frame can make that subtraction underflow. The wrapped unsigned
length is passed to `memcpy`, producing a large out-of-bounds write through the
packet buffer until the processor faults, and allowing corruption before the
fault occurs. This defect is
[CVE-2023-24820](https://github.com/RIOT-OS/RIOT/security/advisories/GHSA-vpx8-h94p-9vrj).

# Bug Description

The GNRC ping command parses its `-s` payload-size argument with `atoi` and
stores the result in an unsigned length without rejecting negative values. A
negative size can therefore become a value near `SIZE_MAX` before it reaches
the ICMPv6 echo builder.

`gnrc_icmpv6_echo_build` adds the echo-header size to that length without an
overflow check. The sum wraps to a small allocation, but the payload-filling
loop still uses the original large length and writes beyond the packet buffer.
The overwrite can corrupt global interrupt-dispatch state and redirect a later
callback to invalid memory. The command must reject negative sizes, and the
builder must reject any length greater than `SIZE_MAX - sizeof(icmpv6_echo_t)`.

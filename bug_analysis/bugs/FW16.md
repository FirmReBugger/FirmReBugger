# Bug Description

`Modbus::process_FC15` handles Write Multiple Coils. It decodes an attacker-controlled starting coil offset and coil count, then computes a packed-coil slot for each requested bit. The slot calculation effectively divides `offset + loop_index` by 16 because each `au16data` element stores sixteen coils.

The global `au16data` array contains only sixteen halfword entries, but the handler never verifies that the calculated slot remains below that capacity. Large offsets or counts therefore make the read-modify-write operation address halfwords beyond the array. The overwritten memory is attacker influenced because each request bit determines how the selected halfword is modified.

In this layout, sufficiently distant slots reach fields of the global `Modbus` object, including its output-stream pointer. The write may complete without an immediate fault; `Modbus::sendTxBuffer` later follows the corrupted C++ object pointer and virtual table while transmitting a response. The handler must bound the maximum packed slot before modifying `au16data`.

# Bug Description

This is **CVE-2023-1422**. `send_cmd` removes an HCI command buffer from the host command queue, stores an extra reference in `bt_dev.sent_cmd`, and passes the buffer to the active H4 UART driver. The driver's `h4_send` routine enqueues that same buffer on its transmit FIFO until UART transmission completes.

If a command-completion event arrives before the UART has removed the outgoing buffer from the transmit FIFO, `bt_buf_get_cmd_complete` optimistically reuses `bt_dev.sent_cmd` as storage for the incoming event. Receive processing then appends the same buffer object to the H4 receive FIFO.

One intrusive list node is now linked into both transmit and receive FIFOs simultaneously. Removal or release by either side corrupts the other list's ownership, allowing double processing, premature free, or use after free. Completion processing must not reuse `sent_cmd` while the driver still owns it, or it must allocate independent receive storage and maintain explicit reference/list ownership.

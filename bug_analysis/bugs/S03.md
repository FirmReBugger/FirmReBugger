# Bug Description

`fnDoCommand` implements a debug-console memory-modification command. It parses the destination token with `fnHexStrHex` and uses the result directly as the target of a byte, halfword, or word store. The value token is parsed separately and written with no intervening address validation.

The command also includes a Flash-oriented branch that passes the input-derived destination to `fnWriteBytesFlash`. That helper prepares or programs memory using the same untrusted address. Neither branch restricts the destination to an authorized RAM, Flash, or peripheral range.

A user who can reach the console therefore has an arbitrary-memory-write primitive. Invalid destinations merely make the defect visible as a fault; mapped choices can silently modify application data, callbacks, control structures, or persistent code. The command must enforce an explicit destination allowlist, access width, alignment, and length before writing.

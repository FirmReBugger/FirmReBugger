# Bug Description

`rpl_ext_header_srh_update` processes type-3 RPL source-routing headers. It
derives the number of addresses encoded in the routing header (`path_len`)
from the header length, address-compression fields, and padding, then uses
`segments_left` to select the next address.

The function does not reject a nonzero `segments_left` value that is greater
than `path_len` before evaluating `path_len - segments_left`. Because the
result is stored in an eight-bit index, the subtraction wraps instead of
remaining negative. For example, a path length of zero and one segment left
produces an index of 255.

The wrapped index is multiplied by the compressed-address size and added to
the routing-header base. A malformed source-routing header can therefore make
the implementation select an address beyond the encoded route and outside
the packet data that was received, leading to invalid memory access and
memory corruption during IPv6 forwarding.

The triggering fields are supplied by network input and require no unusual
peripheral state.

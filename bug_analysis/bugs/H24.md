# Bug Description

The IPHC encoder obtains an extension header from `pkt->next->next` and may
remove that entire snippet after consuming its data. The decoded IPv6 header
can nevertheless advertise another compressible next header, causing the
encoder loop to continue.

On the next iteration the code again dereferences the next packet snippet
without checking that one remains. A crafted forwarded packet can therefore
turn the earlier whole-snippet removal into a NULL-pointer dereference and
hard-fault denial of service. This defect is
[CVE-2023-24822](https://github.com/RIOT-OS/RIOT/security/advisories/GHSA-8x69-5fhj-72wh).

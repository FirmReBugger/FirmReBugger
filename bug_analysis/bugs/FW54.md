# Bug Description

This is **CVE-2021-3329**. During Bluetooth initialization, `bt_init` reads `le_max_num` from the controller's LE Read Buffer Size response and calls `k_sem_init` for the LE packet semaphore with both the initial count and limit set to that value.

If the controller reports zero packet credits, the call becomes `k_sem_init(sem, 0, 0)`. Zephyr's semaphore initializer rejects a zero limit before initializing the embedded wait queue and returns an error. `bt_init` does not check that return value and continues with the semaphore structure still filled with zeroed BSS state.

Later, the connection transmit path reaches `send_frag` and calls `k_sem_take` on that object. The pending path attempts to append the current thread to the semaphore's wait queue. Because the queue was never initialized, its tail pointer is NULL and `sys_dlist_append` writes through that NULL pointer. Initialization must reject the controller response or propagate the `k_sem_init` failure before the semaphore becomes visible to transmit code.

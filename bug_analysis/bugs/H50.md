# Bug Description

`att_send_req` saves the current state of `req->buf` and then dereferences that buffer to prepare and transmit an ATT request. Its entry path does not independently check `req->buf` for NULL. A send failure can clear the field, so calling `att_send_req` again on the same request object would dereference NULL.

The normal direct-send path receives a newly populated request. The queued path pops a request that has not yet been attempted. Response handling releases the completed request's buffer, destroys the request object, clears the active pointer, and advances to a fresh queue node.

# False Positive Reason

The only source path that can retry the same request object after its buffer was cleared is the SMP security-retry branch. This firmware is built without `CONFIG_BT_SMP`, so that branch and its supporting functions are absent. Every compiled invocation therefore supplies a fresh request with a populated buffer, making the NULL-buffer resend unreachable.

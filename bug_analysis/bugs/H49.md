# Bug Description

Bluetooth peripheral connection-parameter updates use a delayed-work item backed by a kernel timeout node. Submitting the same work item while it is already pending would attempt to link one intrusive node twice and corrupt the timeout list.

The vulnerable pattern can arise when automatic initiation and connection setup both schedule the same update without coordinating ownership or pending state.

# False Positive Reason

This firmware includes the Zephyr fix that serializes those scheduling paths and prevents submission when the connection-parameter work item is already pending. Initialization and resubmission therefore operate only on a detached node. The entry represents a historical regression condition that is fixed in this build.

# Bug Description

`HAL_I2C_Mem_Write` stores the caller's transmit-buffer address in the global `hi2c1.pBuffPtr` handle field. The blocking wrapper supplies a stack-local byte, so the address becomes stale as soon as the wrapper returns even though the handle continues to retain it.

`I2C_ITError` assumes the pointer belongs to an active transfer. Its error-recovery path writes through `pBuffPtr` without validating the pointer's lifetime. If the handler ran after the blocking write returned, that byte would overwrite whichever later stack frame reused the address and could corrupt saved registers, pointers, or return state.

# False Positive Reason

Error-interrupt delivery on the STM32F103RB requires `I2C_CR2.ITERREN`. The blocking memory-write path polls flags and does not enable the I2C interrupt sources. The separate asynchronous path clears them before releasing the bus. The stale address therefore exists only while the physical peripheral is unable to invoke the error handler. The enable requirements are documented in [RM0008](https://www.st.com/resource/en/reference_manual/rm0008-stm32f101xx-stm32f102xx-stm32f103xx-stm32f105xx-and-stm32f107xx-advanced-armbased-32bit-mcus-stmicroelectronics.pdf).

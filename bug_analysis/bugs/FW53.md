# Bug Description

This is **CVE-2021-3323**. `uncompress_IPHC_header` calculates the size of the compressed 6LoWPAN IPHC header from packet metadata and then removes or shifts that header within the packet buffer. The vulnerable code assumes that the declared compressed header is fully present.

If `compressed_hdr_size` is greater than `pkt->buffer->len`, the buffer-length adjustment underflows instead of rejecting the truncated packet. That wrapped size flows into `memmove`, converting a small malformed frame into a copy length close to four gigabytes.

The oversized move overwrites packet storage and then adjacent RAM, so later failures may occur in scheduler, driver, or interrupt code rather than in the decompressor. The required invariant is direct: `compressed_hdr_size` must not exceed the bytes held by the packet buffer. The upstream fix implements that comparison and returns an error before performing the move.

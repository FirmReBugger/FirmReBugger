# Bug Description

`ProcessRadioRxDone` reads the first MAC-header byte without first requiring a
nonempty received payload. For a zero-length frame, that access is already one
byte beyond the payload and increments the header length to one. If the stale
byte selects `FRAME_TYPE_PROPRIETARY`, the function computes
`size - pktHeaderLen` as an unsigned 16-bit length, wrapping zero minus one to
65,535.

The wrapped length is passed to `memcpy1`, which copies from the received radio
buffer into the fixed 255-byte `MacCtx.RxPayload` array. The resulting overwrite
can corrupt application, kernel, and control-flow state, causing denial of
service or code execution. This defect is
[CVE-2022-39274](https://github.com/Lora-net/LoRaMac-node/security/advisories/GHSA-7vv8-73pc-63c2).

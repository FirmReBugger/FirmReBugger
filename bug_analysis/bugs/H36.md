# Bug Description

`conn_cleanup` dequeues a `net_buf` from a connection queue and reads the four-byte `user_data` area embedded in that buffer. It interprets the bytes as a pointer and, when the value is nonzero, passes it directly to `tx_free`.

The `user_data` member is declared as untyped scratch storage, not as a dedicated `net_buf *` field. Other paths may store callback identifiers, counters, tags, or subsystem-specific values there. `tx_free` nevertheless treats the supplied value as a valid buffer object: it writes to fields through the pointer and appends the object to the free queue.

If the scratch bytes contain a non-pointer value, cleanup converts that value into an arbitrary write target and queue node. The code needs explicit ownership/type information or a dedicated typed pointer field, and it must validate that the referenced buffer belongs to the expected pool before freeing it.

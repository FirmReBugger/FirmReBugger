# Bug Description

`Modbus::process_FC16` handles Write Multiple Registers. It obtains a starting register offset and count from the request, decodes two bytes for each value, and stores the resulting halfword directly into `au16data[offset + loop_index]`.

The global array has sixteen halfword entries, but no check ensures that the starting offset or final `offset + count` lies within those sixteen slots. An oversized range therefore performs sequential halfword writes beyond `au16data`, with the stored values controlled by the request payload.

Objects located after the array include the global `Modbus` instance. An out-of-bounds register write can overwrite its output-stream pointer; the corruption becomes visible later when `sendTxBuffer` dereferences that pointer to perform a virtual write. The request range must be validated before any register value is committed.

# Bug Description

`sio2host_init` configures SERCOM0 before registering the driver's interrupt
callback. If the handler runs during that interval, `SERCOM0_Handler` loads the
still-zero callback-table entry and branches through it, transferring control
to address zero. The violated invariant is that interrupt dispatch must not
consume a callback until registration has completed.

# False Positive Reason

On the ATSAMR21G18A, SERCOM0 can become active only when a peripheral interrupt
flag and its matching interrupt enable are both set and the NVIC line is
enabled. USART interrupt enables reset clear, so hardware cannot deliver this
handler before the firmware configures those enables and registers the
callback. The early dispatch is therefore created by synthetic interrupt
injection rather than a supported device ordering. See the
[*Atmel | SMART SAM R21 Datasheet*, Atmel-42223G, sections 9.2.2, 24.5.5 and 24.8.6](https://ww1.microchip.com/downloads/en/DeviceDoc/SAM-R21_Datasheet.pdf).

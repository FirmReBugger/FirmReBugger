# Bug Description

This defect is tracked as CVE-2020-12140.

`input_l2cap_frame_flow_channel` reads a 16-bit length from an incoming BLE
L2CAP frame and uses it to append payload bytes to a channel's 1280-byte
reassembly buffer.

For the first fragment, the function subtracts the two-byte L2CAP header and
passes the remaining length directly to `memcpy` without checking it against
the buffer capacity. For a continuation fragment, it adds the new length to
the channel's current write index, again without checking that the combined
extent remains within the buffer.

An oversized length therefore makes `memcpy` write beyond the channel buffer
and into adjacent stack state. The corruption can alter saved registers and
return state, allowing attacker-controlled packet data to redirect control
flow when the function returns.

The length is taken from received protocol data, so the overflow is remotely
reachable through a malformed radio frame processed by the BLE-L2CAP
adaptation layer.

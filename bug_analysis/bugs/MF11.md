# Bug Description

`cmd_attach` resolves the user-supplied device name with generic `device_get_binding` and passes the result directly to `can_attach_workq`. Device binding proves only that a named object exists; it does not prove that the object is a CAN controller.

The CAN attach wrapper interprets the object's API table as `can_driver_api` and loads the attach callback from the CAN-specific slot. If the name identifies another subsystem, the code calls an unrelated table entry with CAN-shaped arguments or follows an invalid pointer.

The command must check that `dev->api` is the expected CAN API table, or use a typed lookup, before attaching filters and callbacks.

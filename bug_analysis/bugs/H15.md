# Bug Description

This is **CVE-2020-14936**. `snmp_oid_decode_oid` decodes a BER-encoded object identifier into a caller-supplied array containing space for sixteen 32-bit OID components. The input controls both the number of encoded components and whether each component occupies one or several bytes.

The decoder advances through the encoded OID and writes each completed component into the next output slot. It has no destination-capacity parameter and does not compare the output index with sixteen before storing. An OID containing more than sixteen decoded components therefore writes first beyond the array and then sequentially through adjacent memory.

Depending on where the destination array resides, the overflow can corrupt neighboring globals, stack locals, saved registers, or return state. The decoder must receive or derive the output capacity and reject another component once all sixteen slots have been used. Multi-byte BER components that fit within the input and output bounds must remain valid. The defect is reachable through ordinary network SNMP content on the CC2538 target.

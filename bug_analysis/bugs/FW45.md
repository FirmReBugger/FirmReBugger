# Bug Description

`USB_OTG_FS_Interrupt` reads the `CHNUM` field from the OTG_FS receive-status register and passes it through `fnProcessInput` and `fnUSB_handle_frame` to `fnEndpointData`. The last function multiplies the value by the size of an endpoint record and adds it to a fixed table base.

No software check verifies that the channel number is smaller than the number of endpoint records allocated by this firmware. An out-of-range value selects memory beyond the table. Subsequent field loads can interpret uninitialized or unrelated words as buffer pointers and dereference them.

# False Positive Reason

`GRXSTSPR.CHNUM` is generated by the OTG_FS core for a channel the peripheral is actively using; it is not a field controlled directly by USB packet bytes. Physical hardware bounds it to the configured endpoint/channel set. The out-of-range number requires unconstrained mutation of the emulated status register and cannot be produced by real USB traffic.

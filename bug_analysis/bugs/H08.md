# Bug Description

After decompressing an unfragmented packet or a first 6LoWPAN fragment, the
input path copies the remaining payload into the selected destination buffer.
The old code checks a required size against the global IPv6 buffer, but does
not verify that `uncomp_hdr_len + packetbuf_payload_len` fits the actual
`buffer_size` passed for the current fragment context.

A malformed first fragment can therefore make the payload `memcpy` cross the
end of its selected 148-byte `frag_info.first_frag` storage and corrupt the
adjacent reassembly context.
The later upstream fix adds the missing destination-capacity comparison before
the copy.

# Bug Description

This is **CVE-2021-3323**. The 6LoWPAN IPHC decompressor derives `compressed_hdr_size` from the received packet and uses it to adjust the packet buffer before reconstructing the uncompressed header.

The vulnerable implementation does not verify that the buffer contains all bytes claimed by `compressed_hdr_size`. A truncated or inconsistent packet can therefore make `compressed_hdr_size` exceed `pkt->buffer->len`. Subtracting the larger header from the smaller buffer wraps an unsigned length to a very large value.

That wrapped length is consumed by the subsequent memory move, which overwrites far beyond the packet allocation and corrupts unrelated RAM. The fix is to compare `compressed_hdr_size` with the current buffer length and reject the packet before any subtraction or move when the declared header is too large.

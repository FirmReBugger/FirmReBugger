# Bug Description

This is **CVE-2023-1902**. `bt_le_create_conn_ext` and `bt_le_create_conn_legacy` create a `struct bt_hci_cmd_state_set` on the caller's stack. `bt_hci_cmd_state_set_init` stores that object's address in the global `cmd_data[net_buf_id(buf)].state` entry so command completion can update the target connection state.

`hci_cmd_done` reads the stored state pointer and applies it with `atomic_set_bit_to(state->target, state->bit, state->val)`. After applying the state, the vulnerable version does not clear `cmd(buf)->state`. Once the connection-creation caller returns, the global field therefore points into an expired stack frame.

If the controller sends a second completion or status event for the same command-buffer slot before a new command replaces the field, `hci_cmd_done` follows the dangling pointer and writes through whatever values occupy the old structure. Completion must consume and clear the state reference exactly once, with duplicate events rejected or ignored.

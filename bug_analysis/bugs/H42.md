# Bug Description

This is **CVE-2023-0397**. The Bluetooth controller's LE Read Buffer Size response supplies `le_max_len` and `le_max_num`. A response with a nonzero maximum packet length but a zero packet count is internally inconsistent and must be rejected.

The vulnerable `bt_init` path passes `le_max_num` directly as both arguments to `k_sem_init` for the LE packet-credit semaphore. With a zero packet count, the call uses an initial count and limit of zero. The semaphore implementation rejects the zero limit before initializing its internal wait queue, but `bt_init` ignores the error.

Bluetooth setup therefore completes with a published, all-zero semaphore. When connection transmit code later takes it, the kernel attempts to link a waiter through NULL wait-list pointers. The response must be validated before semaphore creation, and any initialization failure must stop Bluetooth startup.

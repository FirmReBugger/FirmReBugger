# Bug Description

`USB_SendStringDescriptor` uses the USB control request's requested length to
allocate a variable-length descriptor buffer on the stack. It does not bound
that length against the space between the current stack pointer and the end of
static data. A sufficiently large request therefore moves the stack into the
firmware's global-data region, and the descriptor-building loop overwrites
unrelated persistent objects before the function restores the stack pointer.

The resulting corruption can remain latent until a damaged object is used.
The fix is to cap the requested descriptor length to both the descriptor's real
size and a fixed buffer capacity, rather than allocating host-selected stack
space.

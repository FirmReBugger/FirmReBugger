# Bug Description

The `ccnl_open` shell path starts CCN-Lite again even though its global event
timer already owns a scheduled event. Reinitializing the timer clears the live
event-list head without canceling the outstanding low-level timer callback.
When the RTC later dispatches that callback, the event handler expects a valid
head and updates the next event through a null pointer.

The command must either reject repeated initialization or stop and remove all
pending events before rebuilding the shared timer. A first initialization, or a
restart after the timer has been fully drained and canceled, does not have the
invalid state.

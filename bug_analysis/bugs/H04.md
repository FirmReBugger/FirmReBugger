# Bug Description

This defect is tracked as CVE-2023-29001.

When Contiki processes an IPv6 routing header, the RPL source-routing update
replaces the packet destination with the header's next hop. The affected
version forwards the updated packet without rejecting a next hop that is one
of the node's own addresses.

`tcpip_ipv6_output` treats a local destination as loopback and calls
`packet_input`. The routing header is processed again, leaves a local next hop
in place, and returns to `tcpip_ipv6_output`, creating unbounded recursion
between the input and output paths. A crafted routing header therefore grows
the stack until it corrupts adjacent state or faults.

The fix adds an explicit rejection for own, multicast, unspecified, and
loopback next-hop addresses before forwarding.

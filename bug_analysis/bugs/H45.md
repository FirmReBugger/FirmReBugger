# Bug Description

This is **CVE-2023-1901**. `bt_hci_cmd_send_sync` creates a `struct k_sem sync_sem` on its stack, initializes it, and stores its address in the global `cmd_data[net_buf_id(buf)].sync` record. It queues the command and waits on that semaphore for up to the ten-second HCI command timeout.

If the controller does not respond before the timeout, the function returns an error. Its assertion that the wait succeeded is compiled out in release builds, and no return path clears `cmd(buf)->sync`. The stack frame disappears while the global record continues to point at the former `sync_sem` storage.

A late completion, or reuse of the same small command-buffer slot, makes `hci_cmd_done` observe the non-NULL stale field and call `k_sem_give` through it. The semaphore operation writes into whatever variables now occupy that stack address. Every exit from `bt_hci_cmd_send_sync` must clear the global reference, and completion handling must not use a synchronization object whose owner has timed out and returned.

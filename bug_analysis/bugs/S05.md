# Bug Description
`cmd_net_pkt` parses its argument as an integer pointer and rejects only a
failed conversion or the value zero. Every other value is cast directly to
`struct net_pkt *` and passed to the packet-information routines.

`net_pkt_buffer_info` immediately reads `pkt->buffer`, followed by the packet
reference count and fields from the resulting buffer chain. The command never
checks that the pointer is an aligned, live object belonging to one of the
firmware's packet slabs. A nonzero address supplied through the shell can
therefore cause invalid memory reads, peripheral side effects, or a processor
fault.

The command must validate packet-pool membership, object alignment, ownership,
and liveness before dereferencing the supplied address.

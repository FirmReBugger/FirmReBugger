# Bug Description

`FirmataParser::processSysexMessage`'s `STRING_DATA` handler computes
`bytec = sysexBytesRead - 1` and passes it to `decodeByteStream(bytec,
bytev)`. `sysexBytesRead` is an
unsigned count of data bytes received before the sysex terminator. For a
**zero-length** SysEx message — no data bytes at all, just the sysex start,
command byte, and immediate end — `sysexBytesRead` is `0`, and `0 - 1`
underflows to `0xFFFFFFFF`.

`decodeByteStream`'s loop runs until its index reaches `bytec`. With
`bytec` now effectively unbounded, the loop keeps decoding and writing
bytes in place far past any legitimate buffer, corrupting memory until it
eventually crashes somewhere else entirely, once enough unrelated state
(often whatever dispatch table a later interrupt handler relies on) has
been overwritten. The loop bound is effectively unbounded after the
underflow.

Sending a SysEx message with zero data bytes is ordinary, attacker-reachable
Firmata protocol input.

# Bug Description

`_6lo_frag_size` computes a subsequent fragment's payload length by
subtracting `sizeof(sixlowpan_frag_n_t)` from the packet snippet size. It does
not reject snippets shorter than the four-byte fragmentation header.

For a truncated fragment, the unsigned subtraction wraps to a very large
length. `_rbuf_add` later uses that value as a copy size, writing beyond the
reassembly packet buffer and corrupting memory before a hard fault stops the
system. This remotely triggerable denial-of-service and memory-corruption
defect is
[CVE-2023-24821](https://github.com/RIOT-OS/RIOT/security/advisories/GHSA-2fpr-82xr-p887).

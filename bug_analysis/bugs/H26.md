# Bug Description

This is **CVE-2023-24825**. `gnrc_pktbuf_mark` splits or advances packet snippets when a caller marks bytes as belonging to another protocol layer. When only part of an aligned snippet is consumed, the function advances the data pointer as expected.

When the requested mark consumes the entire aligned snippet, the vulnerable branch sets `pkt->data` to NULL but leaves the snippet node linked into the packet chain. Its successful return makes callers believe the retained node is still a usable packet fragment.

Later 6LoWPAN and IPHC processing traverses the chain and dereferences the node's NULL data pointer. The resulting fault can be triggered by a crafted frame and causes denial of service. The function must remove the empty node, transfer ownership correctly, or make callers handle an explicitly empty snippet instead of returning a live node with no data.

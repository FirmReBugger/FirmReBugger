# Bug Description

`OLED::drawHeatSymbol` scales its unsigned input by dividing it by 12, then computes `10 - scaled_input` as a rectangle coordinate passed to `drawFilledRect`. For inputs from 0 through 131, the coordinate remains within the intended range.

At an input of 132, the quotient becomes 11 and the unsigned subtraction wraps to 255. The rectangle loops then iterate across a coordinate range far larger than the OLED page, allowing indexes beyond the 96-byte-per-page backing buffer. Larger values produce the same class of wrapped bound and out-of-bounds writes.

# False Positive Reason

Both callers obtain the argument from `getTipPWM`. The only setter, `setTipPWM`, clamps every programmed PWM value to at most 100 before storing it. No other call path supplies a raw or external value to `drawHeatSymbol`. The arithmetic defect is latent, but its dangerous input domain is unreachable in this firmware.

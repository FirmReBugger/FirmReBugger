# Bug Description

`control_callback` handles class- or interface-specific USB control requests. It accepts an `iChannel` value from the incoming request and uses it directly to index parallel per-interface state tables. The only bound in the function clamps an unrelated copy length; it never validates the channel against the number of configured interfaces.

An out-of-range channel makes the table lookup read an arbitrary word beyond the interface state. The function transforms that word into an offset used to calculate the destination of a subsequent `uMemcpy`. Because both the source table value and derived destination are unchecked, a sufficiently large channel can make the copy target overlap `control_callback`'s own stack frame.

The copy can overwrite saved registers and the saved return address. When the function restores its frame, it loads the corrupted word into the program counter and transfers control to attacker-influenced data. The handler must reject channels outside the configured interface table before any indexed read or destination calculation.

# Bug Description

This defect is tracked as CVE-2023-28116.

The BLE L2CAP driver returns `BLE_L2CAP_NODE_MTU` from its `max_payload`
callback. In these builds that value is 1280, but the global `packetbuf` used
by the MAC and 6LoWPAN paths is only 128 bytes.

6LoWPAN uses the advertised MAC capacity when deciding whether header and
payload copies fit and whether fragmentation is required. It can consequently
copy compressed headers or an unfragmented payload beyond `packetbuf`.
The L2CAP transmit process can independently copy a fragment sized from the
same MTU into that undersized buffer.

The upstream correction reduces the default L2CAP MTU to `PACKETBUF_SIZE` and
adds a remaining-capacity check before the transmit copy.

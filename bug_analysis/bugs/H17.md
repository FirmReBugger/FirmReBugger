# Bug Description

Contiki-NG's
[`snmp_oid_copy`](https://github.com/contiki-ng/contiki-ng/blob/release/v4.4/os/net/app-layer/snmp/snmp-oid.c#L185-L198)
accepts only source and destination pointers. It copies 32-bit OID components
until it reads the `0xffffffff` sentinel and then copies that sentinel as well;
neither the source extent nor destination capacity is supplied or checked.

Every call site in this firmware uses a 16-word destination. A decoded OID that
uses all sixteen component slots has no in-array room for the required
sentinel; the adjacent varbind value-type field is then populated as ordinary
message decoding continues. The copy fills destination index 15 and continues,
reads source index 16 outside the OID array, and writes that word to destination
index 16 outside the fixed destination. Repeated iterations can corrupt
adjacent varbind or stack state.

A correct fix passes the destination capacity to `snmp_oid_copy` and rejects
any source whose components plus required sentinel do not fit. A sentinel in
the last available slot remains valid and must not be rejected.

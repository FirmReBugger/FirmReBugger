# Bug Description

The Bluetooth controller supplies HCI ACL packets to `bt_spi_rx_thread` over
SPI. The thread reads the packet header's 16-bit payload length and passes that
length directly to `net_buf_simple_add_mem`. The destination is a fixed-size
receive buffer, but this path does not verify that the requested payload fits
the buffer's remaining tailroom. A controller packet declaring an oversized
payload therefore drives `memcpy` past the end of the allocation and corrupts
adjacent kernel and device state.

The violated invariant is that an append may proceed only when the current
length plus the requested length does not exceed the buffer capacity. The
minimal fix is to reject the packet or clamp the copy before the append. The
out-of-bounds write can corrupt control-relevant objects and cause faults in
unrelated interrupt or thread code long after the receive operation.

This defect is [CVE-2020-10065](https://docs.zephyrproject.org/latest/security/vulnerabilities/2020.html#cve-2020-10065).

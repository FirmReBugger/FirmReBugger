# Bug Description

The 6LoWPAN reassembly path allocates a buffer using the datagram size encoded
in the incoming fragment and checks only the compressed fragment offset and
length against that size. When `gnrc_sixlowpan_iphc_recv` later expands the
compressed IPv6 header, it does not resize a fragmented packet or verify that
the uncompressed header plus payload still fits.

The final payload `memcpy` consequently writes beyond the IPv6 packet snippet
when header expansion makes the required size larger than the reassembly
allocation. The overflow can corrupt adjacent packets and allocator metadata,
leading to denial of service or a controlled write primitive. This defect is
[CVE-2023-24819](https://github.com/RIOT-OS/RIOT/security/advisories/GHSA-fv97-2448-gcf6).

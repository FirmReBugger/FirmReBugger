# Bug Description

This is **CVE-2023-24818**. The IEEE 802.15.4 receive path can construct a GNRC network-interface header whose source-address length is zero. Fragment handling passes that empty source to `gnrc_sixlowpan_frag_vrb_get`.

The VRB table also uses a zero source length to mark an unused entry. The lookup can therefore mistake a zero-initialized free slot for a matching route and return it as though it contained valid forwarding state. That entry's interface PID remains zero.

The forwarding path builds a new network-interface header from the empty entry. `gnrc_netif_get_by_pid(0)` returns NULL, but `gnrc_sixlowpan_dispatch_send` passes the unchecked interface into the send path, causing a NULL dereference. Fragment lookup must distinguish an empty source from an unused table slot or reject source-less fragments before creating forwarding state. A crafted fragmented frame can remotely cause denial of service.

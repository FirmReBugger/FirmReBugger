# Bug Description
The shell's `rpl-set-root` command (`cmd_rpl_set_root`) is documented as
taking a mandatory `0/1` argument plus an optional prefix. It splits its
argument string on the first space to separate the two, then compares the
first token against `"1"` with `strcmp` to decide whether to set or clear
the node's root status.

The argument string it receives is NULL when the command is typed with no
arguments at all, and nothing in `cmd_rpl_set_root` checks for that before
handing the pointer straight to `strcmp`. `strcmp` immediately dereferences
its first argument to read a byte, so a NULL argument string crashes the
firmware on the spot.

Since the shell accepts and dispatches arbitrary user input, running
`rpl-set-root` with no arguments crashes the firmware every time — no
special formatting or edge-case input is needed, just the omission of the
argument the help text says is required.

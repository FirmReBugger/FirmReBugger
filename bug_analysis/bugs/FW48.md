# Bug Description

When the Bluetooth controller transport fails to send an HCI command,
`hci_tx_thread` enters its completion-error path. The command buffer remains
available, but the caller passes `NULL` to `hci_cmd_done` instead of that
buffer. `hci_cmd_done` assumes the argument is valid and immediately reads its
pool metadata, producing a null-pointer dereference while attempting to report
the transport failure.

The missing invariant is that every call to `hci_cmd_done` must carry the
corresponding non-null command buffer. Passing the original buffer on the error
path preserves that contract and lets the completion handler release and
account for it correctly. Without the fix, ordinary SPI errors or controller
timeouts can turn a recoverable transport failure into a firmware crash.

This defect is [CVE-2020-10066](https://docs.zephyrproject.org/latest/security/vulnerabilities/2020.html#cve-2020-10066), also documented in Zephyr's [GHSA-gc66-xfrc-24qr](https://github.com/zephyrproject-rtos/zephyr/security/advisories/GHSA-gc66-xfrc-24qr).

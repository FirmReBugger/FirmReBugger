# Bug Description

This is [CVE-2023-31129](https://github.com/contiki-ng/contiki-ng/security/advisories/GHSA-x29r-5qjg-75mq).
Contiki-NG's IPv6 Neighbor Discovery handler processes a Router Solicitation
whose source link-layer address differs from the address stored in the current
neighbor entry. It removes the old entry and asks the neighbor table to create a
replacement.

That allocation can fail and return `NULL`, but `rs_input` does not check the
result before copying address and timer fields into the replacement neighbor.
The first field copy therefore derives its destination from a null base and
performs an invalid write. A remotely supplied Router Solicitation can reach
this path while the shared neighbor table cannot provide a replacement entry.

A correct fix checks the result of `uip_ds6_nbr_add` and stops or recovers when
allocation fails. Successful allocations must continue through the normal
neighbor-update path.

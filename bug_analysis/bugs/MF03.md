# Bug Description

After locating the modem clock prefix, `gsm_get_time` tokenizes the timestamp
and retains the returned pointer. When the firmware is updating its first-fix
time, it passes that pointer directly to `strlcpy` without checking for null. A
reply with the expected prefix but no timestamp token therefore supplies a null
source pointer to the copy routine.

The null result is harmless on the branch that skips the copy, but it is a
defect whenever the first-fix update is active. The parser must validate the
token before entering that copy path.

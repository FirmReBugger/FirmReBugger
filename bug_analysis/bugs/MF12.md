# Bug Description

`cmd_detach` uses the generic device registry to resolve a user-provided name and then unconditionally invokes `can_detach`. The registry contains devices from every subsystem, so a successful lookup does not imply a CAN object.

The CAN wrapper casts the foreign device's API table to the CAN layout and calls what it assumes is the detach slot. On a GPIO, UART, or other object, the same offset may contain a different callback or no valid function at all. The resulting type confusion can transfer control through an incompatible pointer.

The handler must verify the resolved object's API type before CAN dispatch and reject names belonging to other subsystems.

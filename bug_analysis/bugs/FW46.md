# Bug Description

This is **CVE-2021-3323**. The 6LoWPAN receive path passes a packet through `ieee802154_recv`, reassembly, `net_6lo_uncompress`, and `uncompress_IPHC_header`. The decompressor derives `compressed_hdr_size` from IPHC metadata and adjusts the packet buffer with a `net_buf_pull`-style subtraction.

The vulnerable version does not first verify that the packet buffer actually contains `compressed_hdr_size` bytes. When a truncated packet advertises a compressed header larger than its available buffer, the unsigned subtraction underflows. The resulting value is passed as the length of a `memmove`; for example, subtracting five bytes too many produces `0xfffffffb` rather than a small negative result.

`memmove` then writes sequentially across essentially the entire address space reachable from its destination, corrupting packet state, globals, stacks, and kernel objects. Failures can surface much later in unrelated threads. The correct fix is to reject the packet whenever `compressed_hdr_size > pkt->buffer->len` before adjusting or moving the buffer.
